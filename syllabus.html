Course Description

This course builds a foundation in how to use AI agents like Claude Code and Codex to build a variety of artifacts, such as websites, writing, images, animations, music, PDFs, data visualizations, and slide decks. Students will develop the professional engineering skills — version control with Git and GitHub, testing, continuous integration, and deployment with GitHub Pages — that make agentic work sustainable and trustworthy. Each week pairs a concept taught in class with a new artifact to build, along with new skills for working with agents, including managing context and tokens, writing agent skills, calling other AI models through APIs, and keeping data separate from the artifacts it ends up in. The course ends with an individual final project of students’ own design. Students will leave with transferable workflow skills, the judgment to know when and how to trust verify AI output, and the ability to use AI tools to teach themselves new domains to tackle harder problems.

Prerequisites

Students should have completed at least one introductory programming course (e.g., CSCI 1012, EMSE 4571, or equivalent). While students will not hand-type much code in this course, they do need to be able to read code, follow code logic, and notice when something is wrong. Most of the code covered in class will be in Python or web languages (HTML, CSS, and JavaScript), though students do no need prior experience with web languages.

Learning Objectives

Having successfully completed this course, students will be able to:

  • Explain how large language models work, including tokens, context windows, and why they make mistakes.
  • Judge when a chat-based AI tool is a good fit for a task and when it isn’t.
  • Use Git and GitHub to track, review, and commit changes to code bases.
  • Skillfully direct AI agents using the agent → code → artifact workflow, so that what you build is reproducible.
  • Manage context and token use to work efficiently with an AI agent.
  • Write and use AI agent skills.
  • Build and deploy websites with HTML, CSS, JavaScript, Quarto, and GitHub Pages.
  • Use code to generate and customize images, animations, sound, PDFs, data visualizations, and slides.
  • Inject data into documents and other AI-generated artifacts.
  • Check AI output with verification loops, and use AI responsibly: verify facts, protect secrets, and disclose your AI use.

How the Course Works

This class is a workshop. Each week has the same rhythm:

  1. Quiz. Class starts with a short, handwritten quiz on the previous week.
  2. Concept. We learn one new idea (how LLMs work, what an agent is, how to inject data into a document, etc.).
  3. Build together. We use that idea in class to make something, hands-on.
  4. Build at home. You take the idea further on your own in that week’s build, due the following week.

Each week pairs a concept (the idea we learn) with a building (the kind of thing we make). Some buildings span several weeks. For example, we work on websites in Weeks 3 through 5, and each week adds a new idea on top of the last. The schedule lists both for every week.

The semester moves in three stages:

  • Weeks 1-2: Foundations, no agents. We use chat-based AI tools, learn how LLMs work, and learn Git and GitHub by hand.
  • Weeks 3-5: Agents and websites. We bring in AI coding agents and build and deploy websites. In Week 5 we switch to the workflow we use for the rest of the semester.
  • Weeks 6-15: New things to build. Each week adds a new skill and a new kind of artifact: writing, images, animation, sound, data-driven documents, PDFs, data visualizations, and slides. You’ll also work on your final project in the second half of the semester.

Agent → code → artifact

From Week 5 on, we build everything the same way. The agent writes the code, you run the code, and the code builds the artifact. We don’t ask the AI to hand us the finished website, image, or PDF directly. Building through code gives you something you can reproduce, it uses far fewer tokens, and it gives you control: if you want to change one thing, you change one line of code instead of re-rolling the whole thing and hoping.

You control Git

Git is how you know what an agent changed. In this class you always control Git yourself, through GitHub Desktop. Never let the agent make commits for you. Review what the agent changed (the diff in GitHub Desktop), check that it works, and then commit it yourself with a message that says what changed.

Assignments

Participation & Attendance

Attendance will be taken and will be part of your participation grade.

In-person attendance is critical as we will spend most of class building things together. You should plan to attend class in person each week.

There will be no option for remote attendance (e.g. zoom), and class sessions will not be recorded. If you have any questions or need special accommodations, send me a message on slack and we can discuss. If you must miss class for an excused absence (e.g. medical issue), please message Professor Helveston and get notes from your fellow classmates.

Multiple absences, inappropriate or unprofessional behavior during class (such as monopolizing discussions or being rude or disruptive), not participating in classroom exercises, and not being prepared for class will result in a poor score for attendance and participation.

Quizzes

There will be 13 short quizzes, one at the start of every class from Week 2 on (check the schedule). Quizzes are handwritten on paper, with no devices or notes. They are conceptual: they test whether you understand the ideas from the previous week (what a token is, what a commit records, why an agent shouldn’t retype your data), not whether you can write code from memory.

Quizzes are short (10 minutes) and are designed to test for fluency and to demonstrate where additional study is needed. Your lowest two are dropped. If you do poorly on one or two, use that as feedback on where you need additional improvement.

The best way to ensure you do well on quizzes is to be active in class and complete your builds on time.

Make up quizzes are not available. If you arrive late, you can take the quiz in the remaining time left, but you will not be given additional time. Make ups will only be allowed for excused absences that are discussed and agreed upon with the professor prior to class. If you contact the professor after class for a make up, it will not be granted unless a true emergency prevented you from attending class that could not have been communicated earlier.

Why quiz at all? Research shows that giving small quizzes throughout a class can dramatically help with retention. It’s a phenomenon known as the “retrieval effect” - basically, you have to practice remembering things, otherwise your brain won’t remember them. The phenomenon and research on it is explained in detail in the book “Make It Stick: The Science of Successful Learning,” by Brown, Roediger, and McDaniel.

Builds

Each week from Week 1 through Week 13 there is a take-home build: you use that week’s concept to make something on your own. There are 13 builds in total, and your lowest build score is dropped.

Every build is submitted as a GitHub repository that includes:

  • the build itself (from Week 5 on, the code that renders your artifact, not just the artifact);
  • the transcript of your work with the AI (your prompts, its responses, and your iterations);
  • from Build 5 on, a short token usage report (we’ll learn how to measure this in Week 5).

Builds are graded on a 0 / 0.5 / 1 scale using the build rubric. You may discuss approaches with your classmates, but every build is your own work.

Final Project

The final project is individual: everyone builds their own project of their own design, using the workflow and the kinds of things we’ve built during the semester. We introduce the project in Week 8 so you have time to think about it. There are two deliverables:

  • Proposal (due Oct 27). A short, high-level description of what you want to build. It’s graded for completion (1 if you submit it, 0 if you don’t). Its purpose is to get you feedback early on whether your idea is a good one and whether it’s well scoped.
  • Final submission (due Dec 8). A link to a GitHub repository with your project and all of its source files, your transcripts, a token usage report, and a 5-minute video about your project posted to YouTube. In Week 15 we’ll learn to build slide decks, which you can use in your video. Graded 0 / 0.5 / 1 using the final project rubric.

I’ll grade the projects before the final exam, and we’ll start the exam period by showcasing a few of them. View the final project overview page for more details.

Final Exam

There will be a handwritten final exam during the final exam period (date set by the registrar). Like the quizzes, it is conceptual and done on paper with no devices or notes, and it covers material from the entire semester. We’ll start the exam period with the final project showcase, then take the exam.

How Builds Are Graded

I want to be upfront about this: most of the build grading is done by Claude. For each build, Claude reads your repository, your transcript, and your token report, checks your work against the rubric below, and drafts a score and feedback. I review those drafts and make the final call. If you think a grade is wrong, ask for a re-grade and I’ll look at it myself.

This is also why your transcript matters so much. It’s the record of how you worked: what you asked for, what you checked, and what you changed.

Build Rubric

Score Meaning What it looks like
1 Complete Every required part of the build is there and works. From Build 5 on, the artifact is built by code in your repo, and anyone could re-run that code to get it back. Your transcript is included and shows you directing the agent, reviewing its work, and iterating. You made the commits yourself, in reasonable steps, with messages that say what changed. From Build 5 on, your token usage report is included.
0.5 Partial A real attempt, but something important is missing or broken. For example: a required part is missing, the artifact doesn’t run or render, the transcript or token report is missing, the agent made the commits, or all the work is in one giant commit.
0 Missing Nothing submitted, or no real attempt (e.g., the submission has nothing to do with the assignment).

Final Project Rubric

The final project is graded on effort: did you take on a real project and see it through?

Score Meaning What it looks like
1 Strong effort The project is ambitious for its scope (including any changes we agreed on from your proposal feedback) and it’s finished. The artifacts are built from source files in your repo using the agent → code → artifact workflow. The 5-minute video clearly shows what you made, how you made it, and what you learned. Transcripts and a token usage report are included.
0.5 Some effort The project is submitted but is small for its scope, mostly unfinished, or doesn’t build from the repo, or one of the deliverables (repo, video, transcripts, token report) is missing.
0 Missing Nothing submitted, or minimal effort.

Rounding

I do not round final grades. Here’s why. Wherever the line is drawn, there will always be students just below or just above, and rounding will only move that bar and create another group of students who are just below and just above. Rounding does not eliminate the issue but rather just shifts it to another group of students. This is why I draw the lines before the course starts - to ensure a fair and transparent system for everyone, that way you don’t have to shoot for a moving bar. To be clear, this means I will not modify or round your final score, even if you’re very close to a different letter grade (e.g., a 93.98 is an “A-” and will not be rounded up to an “A”).

Rather than round, I grade generously throughout the semester. For example, if you give a quiz your best shot and completely fail it, you will likely get a 50% instead of a 0%. The 50% is for trying as learning still happens when you try regardless if you get the question correct (0s are reserved for those who simply don’t attempt it).

AI Tools and Cost

You’ll need two things that aren’t free: an AI coding agent and, starting in Week 7, an API key for generating images. Check Slack before you pay for anything. We are pursuing institutional access, and I’ll post there if we get it. If the cost is a barrier for you, let me know.

An AI coding agent (about $20/month)

I will use and teach Claude Code in class, which requires at least a Claude Pro subscription (about $20/month). You’re welcome to use an alternative, such as Gemini CLI (free with a Google account) or Codex (needs a paid ChatGPT plan). The underlying skills transfer, but in-class instruction and course materials assume Claude Code, so you’re on your own for translating anything tool-specific.

Why a subscription and not the API? Agents burn through a lot of tokens. Paying per token through an API would cost far more than a flat monthly subscription.

An image-generation API key (Week 7 on)

We don’t use Claude to make images. Starting in Week 7, your agent will call Google’s image model (Nano Banana) through the Gemini API. This is paid per image, but if you’re careful it should only add up to a few dollars over the semester. We’ll set up API keys in class, including how to keep them secret (never in your code, never in a commit).

Late Policy

Each student is allowed 3 late build submissions - use them however you want, no questions asked. These are meant to cover illness, family emergencies, and religious holidays.

Beyond those, all other assignments are due by 11:59pm on the assigned due date unless specified otherwise. Assignments submitted up to 24 hours past this deadline will be graded to a max of half credit (0.5 on the 0 / 0.5 / 1 scale). Assignments submitted beyond 24 hours past the deadline will not be graded and will be assigned a 0. The final project cannot use a late submission, since I need time to grade the projects before the final exam.

If you need a special accommodation such as due to an illness, family emergency, or religious holidays, contact the instructor ahead of time.

Re-grades

You may request a re-grade within 7 days of receiving a grade, including any grade that Claude drafted. Send me a message on Slack with the assignment name and what you think was graded incorrectly and why. I’ll review your submission against the rubric myself. If I find an error, I’ll fix the grade. If not, the original grade stands.

Use of AI

Using AI in this course is required. It’s the core skill being taught. Every build and the final project must be made with AI, and you must submit your transcripts.

Now, LLMs are pretty good, but sometimes they suck. Don’t blindly trust them - they will betray you. You are fully responsible for everything you submit, so read what the agent produces, run it, look at the result, and fix it when it’s wrong. That’s what the verification loops we learn in Week 8 are for.

There are three places where AI is not allowed, each for a reason:

  • Week 1 and Build 1 (Git by hand). You can’t supervise an agent that changes your files until you understand version control yourself.
  • Git, all semester. The agent never makes commits for you (see You control Git). Your commits are how you show that you reviewed what the agent did.
  • Quizzes and the final exam. These are handwritten, with no devices, because they test what you understand.

Your transcripts are read by Claude (for grading) and by me, and are used only for grading this course. Before you submit, remove API keys, passwords, and any personal information from them.

I don’t use AI-detection software (it’s unreliable). The record of your work is your transcript and your Git history. I also use AI myself, to help prepare course materials and to draft build grades and feedback, and I review everything before you see it.

Throughout the course we’ll talk about where AI fails, what it costs (in money and energy), copyright and authorship, and when not to use it.

Curious how LLMs actually work? That’s Week 2. If you want a head start, check out this article, which provides a simplified description of how they work (which itself is still quite complicated).

Cheating

Cheating results in a penalty on the first offense, and failing the course on the second offense. Cheating on builds and the final project can include:

  • Submitting someone else’s work or transcript as your own, in any amount.
  • Editing a transcript to hide or fake what happened. (Removing secrets and personal information is fine and expected.)
  • Providing your builds or transcripts to anyone else in the class.
  • Putting solutions to course assignments online.
  • Getting someone else to do the assignment for you.

Cheating on quizzes or the final exam can include:

  • Referring to any external resources while completing it (phones, notes, AI tools, etc.).
  • Copying part of an answer off of another student’s paper, even if it is very small.
  • Using solutions provided by students who previously took the course.

Penalties

Violations will be reported to the Office of Student Rights & Responsibilities. Penalties are decided by the course instructors, and can vary based on the severity of the offense. Possible penalties include:

  • Receiving a 0 on the assignment/quiz in question.
  • Receiving a full letter grade deduction in the course.
  • Automatically failing the course.

Depending on the student’s prior academic history, violations may also be accompanied by a letter to the Dean of Student Affairs, again at the instructors’ discretion. This can lead to university-level penalties, such as being suspended or expelled.

Grace Period

College is a time when you do a lot of learning. Sometimes, you might make bad decisions or mistakes. The most important thing for you to do is to learn from your mistakes, to constantly grow, and become a better person.

Sometimes, students panic and copy someone else’s work right before the deadline, then regret what they did afterwards. Therefore, you may rescind any build submission for up to 24 hours after the deadline with no questions asked. Simply message the course instructors asking to delete the submission in question, and we will do so. Deleted submissions will not be graded. However, it will always be better to get a 0 (or partial credit) on an assignment than to get a cheating violation!

  2. Non-nursing babies and older children are welcome whenever alternate arrangements cannot be made. As a parent of young children, I understand that babysitters fall through, partners have conflicting schedules, children get sick, and other issues arise that leave parents with few other options.

  4. All students are expected to join with me in creating a welcoming environment that is respectful of your classmates who bring children to class.

I understand that sleep deprivation and exhaustion are among the most difficult aspects of parenting young children. The struggle of balancing school, work, childcare, and graduate school is tiring, and I will do my best to accommodate any such issues while maintaining the same high expectations for all students enrolled in the class. Please do not hesitate to contact me with any questions or concerns.
